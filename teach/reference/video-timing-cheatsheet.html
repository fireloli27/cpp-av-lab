视频 PTS / Timing 速查

压缩表。用于区分 frame index、PTS、duration 与 callback arrival；仓库契约以 issue 07 / ADR-0006 为准。

四个时间概念

概念含义不能替代
frame_index本次成功收到帧的顺序号PTS
PTS来源时间轴上的呈现时刻callback arrival
durationsample 覆盖的时长；可能 invalid下一帧 PTS
arrival线程实际处理 callback 的时刻媒体时间

CMSampleBuffer → pts_ns

CMTime presentation = CMSampleBufferGetPresentationTimeStamp(sample);

if (!CMTIME_IS_VALID(presentation)) {
  // manifest 契约要求 PTS；此处应失败
}

int64_t pts_ns =
    round(presentation.value * 1e9 / presentation.timescale);

int64_t relative_pts_ns = pts_ns - first_pts_ns;

CMTime 的单位由 timescale 决定。通常调用 CMTimeConvertScale 再转整数，并明确 rounding rule；不要无检查地做浮点算术。

Issue 07 manifest

frame_index,file,width,height,pixel_format,pts_ns,relative_pts_ns,bytes
  • pts_ns：来源 PTS，整数纳秒。
  • relative_pts_ns：以本批首帧为零点。
  • 不写伪造的 duration；相邻 PTS 差可表示实际时间间隔。

30 fps 不是「每帧必然 33 ms」

nominal interval = 1 / 30 s
                 ≈ 33.333 ms

dropped scenario:
f0   PTS   0.0 ms
f1   PTS  33.3 ms   Δ  33.3 ms
f2   PTS  66.7 ms   Δ  33.3 ms
f3   PTS 133.3 ms   Δ  66.7 ms  ← one-frame-sized hole
f4   PTS 166.7 ms   Δ  33.3 ms

frame index 仍为 0、1、2、3、4；只有 PTS 揭示了 f3 前的时间空洞。多个较大的 delta 需要结合设备、调度和丢帧日志判断，单次抖动不自动等于丢帧。

AVCaptureVideoDataOutput 边界

  • delegate 在指定 queue 上回调，不保证与摄像头采样同时刻执行。
  • alwaysDiscardsLateVideoFrames = YES 时，queue 堵塞可导致 late frame 被丢弃。
  • PTS 来自 sample buffer，不应替换为 now()。
  • 本票 callback 只复制 tight NV12 + PTS；写盘和预览转换移到采集结束后。

A/V 同步边界

07 单视频采集：
camera PTS → manifest

真正的 A/V 同步：
audio timeline + video timeline
→ common clock / playback scheduling

结论：保存 PTS 是必要材料，不是「已经同步」。
