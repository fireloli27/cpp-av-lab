Raw Video Frame / NV12 速查

压缩表。面向 Learning「视频·采集」；术语先服从 GLOSSARY.md，本阶段落地契约见 issue 07 / ADR-0006。

一句话

  • Frame：某一时刻的二维画面；编码前仍是未压缩样本。
  • Pixel：画面中的一个位置；它的字节数由 pixel format 决定。
  • NV12：8-bit 4:2:0，两 plane；Y 在前，交错 Cb/Cr 在后。
  • 420v：Apple 的 NV12 video-range 格式，本仓库采集固定用它。

NV12 几何

width W · height H

Y plane     W × H 个 1-byte samples
UV plane    (W/2) × (H/2) 个 pairs
            每个 pair = [Cb, Cr] = 2 bytes

tight bytes = W×H + (W/2)(H/2)×2
            = W×H×1.5

×1.5 只适用于 8-bit 4:2:0。一个 UV pair 对应 2×2 个 Y 位置，所以 chroma 横纵都按 2:1 子采样。

1280×720 字节账

Y      = 1280 × 720       =   921,600 B
UV     = 640 × 360 × 2    =   460,800 B
------------------------------------------
frame  =                    1,382,400 B
30 帧  =                   41,472,000 B ≈ 39.6 MiB

stride / pitch

visible row bytes ≠ allocated row bytes

Y row:  width
UV row: width/2 × 2 = width

真实 buffer：
rowBytes = CVPixelBufferGetBytesPerRowOfPlane(pb, plane)
rowBytes 可能大于 visible row bytes

tight 文件：
逐行复制 visible row bytes，跳过 row padding

Apple 文档把 CVPixelBufferGetBaseAddressOfPlane 与 CVPixelBufferGetBytesPerRowOfPlane 分开提供，正是因为「起点」和「行跨度」是两件事。

video range

Apple 420v，8-bit：
Y nominal 16…235
Cb/Cr nominal 16…240

不等于 RGB 的 0…255。
预览转换需要正确颜色矩阵与 range。

管线和边界

摄像头
  → Raw Video Frame（AVFoundation / CVPixelBuffer，420v）
  → [编码：本速查未讲]
  → compressed bitstream
  → …
  • PNG 预览是缩略派生证据，不取代原始 NV12。
  • PTS 回答「何时呈现」；帧序号只回答「第几张」。
  • packet、RTP、jitter buffer 都不是采集 stage 的帧字节布局。

出处

  • Microsoft：8-Bit YUV Formats — 4:2:0、stride、NV12 内存布局。
  • Apple：CVPixelBufferGetBytesPerRowOfPlane — plane 的分配行宽。
  • Apple：CVPixelBufferGetBaseAddressOfPlane — plane 起点。
  • Apple SDK CoreVideo/CVPixelBuffer.h — 420v / video-range 常量定义。
