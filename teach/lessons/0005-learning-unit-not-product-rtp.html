知识：为什么本票故意不用 RTP

Learning spec 把「阶段 3 打包是否 = RTP」列为未决（产品侧 U10）。issue 04 仍要练「组织成可环回收发的单元」，所以选了更不容易被读成「产品协议已定」的方案：自定义长度前缀 + POSIX UDP loopback（见 ADR-0003）。

能跑通 learning_audio_local_transport，证明的是单元收发一致，不是「以后 SDK 一定不走 RTP」。WebRTC 对照短文再映射真实 RTP。

知识：本课环回证明什么 / 不证明什么

证明：access unit → Transport Unit → 自发自收字节一致
不证：ICE / TURN / SRTP / 双进程 / 真实丢包抖动
不证：产品必须（或不许）用 RTP

UDP 本身（ RFC 768 ）不保证可靠与顺序；本机 loopback 几乎碰不到这些，所以实验刻意把问题缩到「打包形状 + 收发一致」。

知识：jitter buffer 放哪（只预告）

叙述必会旁路：抖动缓冲通常在接收之后、解码之前，吸收网络抖动。本阶段不实现、不验收——课记里留钩子即可。别把它当成五段之一。
