Opus 是码流，CAF 是盒子

一课目标：分清「编解码器 / 压缩码流」与「文件容器」，并用码率算 1 秒载荷量级——对仗 0001 PCM≠WAV。

知识：编码在管线哪

Glossary「编码」：音频侧把 PCM 样本压成压缩码流。你仓库里的路径是：

capture.wav（PCM in WAV）→ AudioConverter（Opus）→ encode.caf（Opus in CAF）

本阶段不采麦、不做 RTP。AEC 通常在采集后、编码前；弱网自适应会动码率——实验固定 64 kbps，只叙述不实现。细节只维护在课记。

知识：两个不同的词（对仗 0001）

Opus：RFC 6716 定义的编解码器。输出是压缩 packet 组成的码流，适合交互语音量级（文档给出约 6 kbit/s 起的宽范围）。它不是「.caf 文件格式」。

CAF（Core Audio Format）：Apple 的容器——至少有 Description + Data；可变包还要 Packet Table 等。见 CAF Overview。盒子里可以装 Opus，也可以装别的。 

PCM  ≠ WAV
Opus ≠ CAF

能 afplay encode.caf，说明容器+码流都对；网上传输时，04 阶段通常要讨论的是码流单元（packet），不一定整文件扔 UDP。

知识：码率字节账

采集契约：1 秒裸 PCM ≈ 96 000 B（课记）。编码目标码率 64 000 bps → 载荷量级 64000 / 8 = 8000 B/s。CAF 文件会略大（头、pakt、cookie）；课记与 Catch2 用上界防「巨无 free chunk」回归。

实现用系统 AudioConverter（不是 libopus C API）把 PCM 拉成 Opus packet 再写入 CAF——选型见 ADR-0002。
